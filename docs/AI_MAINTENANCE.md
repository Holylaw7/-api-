# AI 修改与维护手册

适用版本：主系统 1.7，独立 AI 助手 1.2。本文供后续接手本项目的 Codex、Claude、ChatGPT、DeepSeek 或其他编程代理使用。它说明修改程序前应读什么、哪些证据不能改写、一个改动需要同步哪些文件，以及怎样把结果交给下一位维护者。

用户日常操作见根目录 [README](../README.md)；全部本机 HTTP 入口见 [API_REFERENCE](API_REFERENCE.md)；每日竞价与收盘结果如何形成持续优化样本见 [CONTINUOUS_OPTIMIZATION](CONTINUOUS_OPTIMIZATION.md)。本文不是给模型扩大权限的授权书。模型仍只能在用户明确指定的项目、账户与操作范围内工作。

## 1. 接手时的固定阅读顺序

1. 读取项目根目录 `AGENTS.md`。它记录当前版本的强制不变量和本机维护目录。
2. 读取 `README.md`、`CONTRACT.md`、本文、`docs/ARCHITECTURE.md` 和 `docs/STRATEGY.md`。
3. 按任务再读专项文档：
   - 每日数据、回放、参数建议：`docs/BACKTEST.md` 与 `docs/CONTINUOUS_OPTIMIZATION.md`；
   - 同花顺接入：`docs/FINANCE_CONNECTION.md`；
   - 模型切换：`docs/AI_ASSISTANT.md`；
   - 报告：`docs/REPORTS.md`；
   - 指定板块：`docs/SECTOR_RESEARCH.md`；
   - 官方补充数据：`docs/OFFICIAL_UPGRADE.md`。
4. 再检查实际源码和测试。接口以 `app/server.py`、`app/ai_studio.py` 为准；策略以 `app/engine.py` 为准；存储以 `app/storage.py`、`app/research.py`、`app/daily_validation.py` 为准。
5. 查看 `git status`，保留用户已有改动。不要为了得到“干净目录”执行硬重置或删除本机数据。

当文档与源码不一致时，先核实测试和真实运行行为，然后在同一次修改中修正源码、测试和文档。不能只改文档掩盖实现问题，也不能只改实现让契约继续过期。

### 项目级与官方同花顺 Skill

仓库内置 [项目级 `auction-lab-finance` Skill](../.agents/skills/auction-lab-finance/SKILL.md)。支持 Agent Skills 的 Codex 或其他维护工具进入本仓库后可以直接发现它；该 Skill 负责把金融接入、竞价证据链、持续优化和验证工作路由到本项目已有文档与源码。它随源码分发，但不被 Python 或网页加载，不会增加运行依赖。

需要完整上游接口目录时，维护 AI 或开发者还可选择安装官方仓库提供的全局 `hithink-finance` Skill：

```powershell
npx skills add HiThink-Tech/Financial-API --skill hithink-finance -g --yes
```

安装后，新会话可用官方 Skill 查找接口资料、选择 REST / CLI / MCP / Python 路径或辅助诊断；维护本仓库时仍先遵循项目级 Skill 与 `AGENTS.md`。两种 Skill 都不授予同花顺账户权限，不包含、保存或验证 API Key，也不是启动竞价研究台所需的组件。项目运行时仍由 `app/provider.py` 调用官方 Financial API，由 `/api/finance/*` 和项目外的用户级凭据完成配置与验证。不要把 Skill 的发现或安装成功写成金融接口认证成功；如果 Skill 说明与本项目源码、测试或当前官方接口不一致，先核验再同步实现与文档。

官方 Skill 的通用路由还包含兼容读取 `API_KEY` / `FUYAO_TOKEN`、安装 CLI、初始化本地库和低频全局自更新等能力。本项目默认不授权这些行为：维护 AI 只使用其文档资料，不读取通用环境变量或其他工具的密钥库，不静默执行 `skills update`，也不安装额外工具或下载全量数据。用户明确要求更新 Skill 时再执行；需要固定版本的受控环境可设置 `HITHINK_FINANCE_NO_SKILL_UPDATE=1`。这条项目级约定不修改上游 Skill 文件，避免破坏来源追踪和更新校验。

## 2. 不得破坏的系统边界

### 2.1 时间与未来数据

- 09:15—09:25 的每批竞价响应必须按本机实际接收顺序立即保存、计算和发布。不能等十分钟收齐后统一分析。
- 盘前上下文只能来自上一交易日或更早。当天收盘涨停池只能作为 `label`，不得参与当天候选选择、因子、分数或排序。
- 主研究时点是 09:24:50；09:26:00 只作终态收尾诊断。09:26 的信息不能进入 09:24:50 的参数选择。
- `data.timestamp` 是上游响应组装时间；回放截止使用本机 `received_at`。不得把二者改称交易所逐笔时间。
- 09:10—09:26 是竞价保护时段。回测、历史导入、外部参数建议、板块批量取数等重任务不能在此期间开始。

### 2.2 原始证据与不可变档案

- `data/market.sqlite3` 中的实盘批次、盘前清单和时点决策不能由调参任务覆盖、删除或重排。
- 每日冻结档案和带收盘标签的核验版本是不同文件；补标签不能改写原竞价分数。
- 报告、每日档案、实验和板块证据都有内容标识。修订必须生成新对象或新版本，不能让旧 AI 回答继续附着在变化后的证据上。
- 演示、实盘和外部导入始终分离。演示数据不能进入真实报告、每日核验或权重实验。
- 测试只用临时目录、临时 SQLite 和模拟网络，不能把夹具写入 `data/`。

### 2.3 缺失、空值与覆盖

- `null`、请求失败、未知和真实的 0 是不同状态。缺失因子不能补 0；接口失败不能描述为“空池”。
- 分数必须和 `factor_coverage`、观察数量、窗口覆盖、数据阶段一起解释。不同因子覆盖的分数不能当作完全同质样本。
- `5天4板` 不等于严格 4 连板。严格连板只使用能够核验的连续事实。
- 成交额、竞价金额和板块活跃度都不等于资金净流入。没有已授权且口径明确的资金接口时，净流入保持未知。
- 只研究“上一交易日完整涨停池”的回测结论不能推广为全 A 股、自选池或趋势池结论。

### 2.4 模型与主算法

- 结构化七因子评分由本机确定性程序完成。没有 AI Key 也必须可以采集、评分、复盘和回测。
- LLM 只能解释白名单摘要或提出待验证建议；不得位于实时采集关键路径，不得回写原始批次、标签或已经发布的排名。
- 外部模型调参只使用 `/api/research/ai-dataset`。不得把保留期标签、完整实验或全日历史出口继续喂给选参模型。
- `/api/research/proposals` 只归档建议。任何模型都不能通过该接口自动修改实盘权重。
- DeepSeek、OpenAI、自定义模型和同花顺金融 Key 分开保存，不能混用或互相回退。

### 2.5 凭据与本机访问

- 不在源码、测试、提示词、日志、报告、截图、Git、ZIP 或浏览器存储中保存任何真实 Key。
- 不输出 Key 尾号、摘要或哈希帮助识别凭据。网页只显示是否配置、来源和验证状态。
- 主程序和独立助手仅监听 `127.0.0.1`。POST 保留本机 Host、同源 Origin 与 `X-Local-App` 检查。
- 固定服务商必须使用 HTTPS，禁止把凭据跟随重定向转发到其他主机。
- 维护者不得为“连通性检查”自动发起付费模型生成。线上验证、协议模拟和离线测试要分别陈述。

## 3. 模块地图

| 位置 | 责任 | 修改时重点 |
| --- | --- | --- |
| `app/engine.py` | 七因子增量评分、质量和排名 | 每批即时计算；缺失不补零；跨日和乱序处理 |
| `app/service.py` | 调度、状态、后台任务、保护时段、模式隔离 | 不在持锁时做长网络请求；任务取消与版本校验 |
| `app/provider.py` | 同花顺官方 HTTP 适配 | HTTP 200 且 `code==0`；分页、限流、脱敏、禁止重定向 |
| `app/storage.py` | SQLite 原始批次、报告、清单、时点决策 | `INSERT OR IGNORE` 冻结证据；live/demo 隔离 |
| `app/replay.py` | 按时点重放历史批次 | 只摄入截止前接收记录；当天结果只作标签 |
| `app/daily_validation.py` | 09:27 竞价冻结、15:10 后收盘核验 | 冻结分数与结果版本分开；不可变写入 |
| `app/optimization.py` | 固定共同样本、时间切分、权重搜索 | 不随机拆股票；保留集只评价一次 |
| `app/research.py` | 实验、AI开发集、导入、建议档案 | 开发集出口不泄露保留标签；建议不应用 |
| `app/review.py` | 收盘盘面、涨停与板块结构 | 明确日期、完整性、分页和统计分母 |
| `app/report_library.py` / `app/reporting.py` | 报告版本、Markdown、AI附录 | 版本绑定、路径和大小限制、转义 |
| `app/selection.py` / `app/stocks.py` | 趋势池与单股日线研究 | 与竞价七因子保持独立；前复权与截止日 |
| `app/sector_research.py` | 指定板块有界取数 | 当前成员不是历史成员；请求和样本上限 |
| `app/llm.py` / `app/ai_gateway.py` | 模型摘要与多服务商协议 | 白名单、服务商隔离、不自动重试付费请求 |
| `app/server.py` | 主系统本机 HTTP | 与 `docs/API_REFERENCE.md` 同步 |
| `app/ai_studio.py` | 8766 独立助手 HTTP | 不隐式启动金融服务；市场摘要须用户勾选 |
| `static/` | 无 CDN 的本机网页 | 不存 Key；旧后台兼容；空数据和错误状态 |
| `tests/` | 行为与边界回归 | 临时数据、模拟网络；测试通过不等于策略有效 |

## 4. 不同修改需要同步什么

| 改动类型 | 至少修改 | 必须复核 |
| --- | --- | --- |
| 调整七因子权重 | `app/config.py` 或用户配置、策略说明 | 历史原分不变；当前权重实验另建档；共同样本一致 |
| 新增/删除竞价因子 | `engine.py`、配置、回放、优化、页面、接口契约、策略文档、测试 | 字段单位、可用时点、缺失规则、与旧因子重复性、历史兼容 |
| 修改候选池 | `service.py`、`selection.py`、策略和数据来源文档、测试 | 盘前可见性、上一交易日对齐、样本选择偏差 |
| 修改优化目标/门槛 | `optimization.py`、`BACKTEST.md`、`CONTINUOUS_OPTIMIZATION.md`、测试 | 旧实验版本和复现摘要；不能因结果不好临时放宽门槛 |
| 新增 HTTP 端点或字段 | server/service、`CONTRACT.md`、`API_REFERENCE.md`、架构、测试 | 本机安全、输入上限、模式/时段、异步语义、脱敏 |
| 新增上游数据源 | provider/纯构建模块、数据来源文档、白名单和测试 | 授权、日期、单位、分页、限流、完整性、失败与空值 |
| 修改 AI 摘要 | `llm.py`、AI文档、白名单测试 | 不含 raw/Key/保留标签；模式、日期、覆盖和缺失仍在 |
| 修改持久化 | 存储类、迁移兼容、契约、备份说明、测试 | 不覆盖旧档；读取上限；原子写；跨版本恢复 |
| 修改页面 | HTML/JS/CSS、浏览器验收 | 未配置、已保存未验证、错误、演示、窄屏和旧后台 |
| 发版/打包 | 版本字段、README、VALIDATION、构建脚本 | ZIP 无 data/凭据；新文档已包含；旧服务升级提示 |

## 5. 标准修改流程

### 5.1 修改前

1. 确认实际项目目录和 `git status`，不要修改历史备份副本。
2. 记录当前版本、基准测试数量及相关真实证据 ID。文档修改不能改动已有报告或实验 ID。
3. 找到调用链：HTTP → service → 纯计算/数据源 → 存储 → 页面，并阅读相应测试。
4. 如果涉及官方字段、模型协议或软件库版本，查阅当前官方资料；把事实来源与本项目的推断分开。
5. 判断是否处于上海时间 09:10—09:26。该时段不要启动重负载测试、回测、批量行情或模型任务。

### 5.2 实现中

1. 优先把计算写成无网络、无磁盘、无当前时间依赖的纯函数。
2. 在 service 层处理权限、模式、时段、任务并发、取消和版本冲突。
3. 在存储层使用不可变版本或原子替换；不能先破坏旧证据再尝试新写入。
4. 接口只返回前端需要的白名单字段。`raw` 可以保存在受控证据中，但不能进入 SSE 或 LLM。
5. 新增限制要返回可操作的中文原因；异常正文不得包含请求体、认证头或上游敏感响应。
6. 新功能默认有界：代码数、日期数、分页数、文件大小、输出条数和重试次数都要明确。

### 5.3 验证与交付

1. 运行相关测试，再运行：

   ```powershell
   python -m unittest discover -s tests -v
   node --check static/app.js
   node --check static/ai.js
   git diff --check
   ```

2. 涉及页面时实际检查空白新用户、真实已配置用户、演示、错误和窄屏状态。
3. 涉及凭据或网络时，自动测试使用临时凭据和模拟网络；真实验证必须由已有授权支持，并记录调用范围。
4. 更新 `docs/VALIDATION.md`，分别写明：离线测试、真实认证、真实交易时段、付费模型、仍未验证事项。
5. 运行 `python tools/build_release.py`；确认分发包没有 `data/`、`.env`、数据库、日志、聊天或真实 Key。
6. 提交说明写最终行为、关键边界和验证结果。不要用“已优化”“准确率提高”代替实际样本、时期和指标。

## 6. 数据备份与恢复

修改算法不需要迁移或清空历史数据。准备高风险存储变更前，先停止监测并复制整个 `data/` 到用户指定的备份位置；不要把备份加入 Git。至少保留：

- `market.sqlite3`：原始批次、报告、盘前清单、时点决策；
- `research/daily/`：每日冻结与核验版本；
- `research/experiments/`：实验 JSON/Markdown；
- `research/holdouts.json`：已经暴露的保留日期；
- `research/proposals/`：外部 AI 建议；
- `reports/` 与 `sector-research/`：收盘报告和指定板块证据；
- `config.json`：当前非敏感策略设置。

用户级金融/模型凭据位于项目外，不应复制进源码备份。恢复时先复制数据到一份隔离项目，使用 `--no-auto-start` 启动并做只读检查，再替换实际运行副本。不得通过删除 `holdouts.json` 把已经看过的日期伪装成新的独立检验。

## 7. 给维护 AI 的任务输入模板

```text
项目：竞价研究台，主系统版本 <版本>，工作目录 <绝对路径>。
目标：<一个具体改动>。
必须先读：AGENTS.md、docs/AI_MAINTENANCE.md、<专项文档>。
当前证据：实验ID <id或无>；报告ID <id或无>；当前权重 <七因子对象>。
允许修改：<文件或模块范围>。
禁止：读取或输出Key；覆盖data；使用演示当实盘；把收盘标签用于盘前因子；自动应用权重。
验收：<需要的测试、页面状态、真实接口范围>。
交付：列出修改、验证、仍未验证事项，并更新相关文档。
```

范围不清时，维护 AI 可以先做只读审计和安全的离线验证；涉及自动应用权重、删除历史、覆盖报告、向第三方发送本机数据或启用真实付费调用时，必须取得用户明确授权。

## 8. 维护交接记录模板

每次改动在最终回复或提交说明中至少留下：

```text
版本/提交：
解决的问题：
最终行为：
接口变化：
数据/模式/时间边界：
新增或改变的文件：
测试结果：
真实联网验证：
未验证事项：
是否改变策略权重：否/是（用户批准记录）
是否改变历史数据：否/是（备份和迁移说明）
```

这份记录用于复现维护过程，不是策略收益证明。任何“有效”“提升”“稳定”等结论都必须同时给出日期切分、样本数、基线、指标、缺失和保留集是否曾被看过。

# 报告保存与历史对比

适用版本：1.3。运行目录：`E:\A股竞价`。本指南区分「联网生成新报告」与「读取、比较、保存本机已有报告」；后面三项不会额外调用行情接口。

## 每日收盘报告怎么保存

1. 双击 `启动系统.cmd`，进入「收盘复盘」。默认自动监测在交易日 15:10 后生成复盘；也可选择已收盘日期，点击「联网生成复盘」，等待完成。
2. 查看「当前显示的报告」中的日期和模式。日期输入框仅指定下一次联网生成请求，修改输入框不会替换已经显示的报告。
3. 检查数据边界：`partial` 表示部分数据缺失或需核验；日期由休市日推断时保留原始快照日期并明确提示。数据不完整时也可保存，缺失不会被改成零。
4. 点击 **「保存 Markdown ↓」**。系统先在本机写入 `E:\A股竞价\data\reports\YYYY-MM-DD.md`，完成后显示路径，并尝试浏览器下载。页面还会提供下载链接，可再次点击。
5. 用支持 Markdown 的编辑器打开 `.md` 文件；普通文本编辑器也能阅读。需要原始证据或二次计算时，另点「导出 JSON」。

本机保存与浏览器下载是两个步骤。只有本机写入成功，页面才会给出成功提示；如果浏览器未弹出窗口，先按提示路径找文件。浏览器下载可能自动保存、弹出询问或直接打开，取决于用户设置；页面不能强制弹出某一种对话框。依据见 [MDN：链接的 download 属性](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/a#download)。

同日期、同版本类型的文件再次保存会原子替换原文件，不会保留每次保存的副本。若要长期保存多个手工版本，请在文件管理器中另复制命名。另存文件只是阅读副本，不会更改本机复盘数据库。

## 保存时附上 DeepSeek 或 ChatGPT 的解释

1. 在「AI 辅助研判」选择服务商，使用该服务自己的 Key；配置方法见 [AI 助手指南](AI_ASSISTANT.md)。
2. 确认当前复盘日期，点击生成文字分析。当前有复盘时，系统只把该份复盘的结构化摘要交给模型，不把今天竞价或另一只股票的独立查询混入历史复盘。
3. 等待回答完成，回到保存区域，勾选 **「附上当前 AI 研判」**，再保存 Markdown。

| 保存类型 | 实盘文件名 |
| --- | --- |
| 普通复盘 | `data/reports/YYYY-MM-DD.md` |
| 附 DeepSeek 分析 | `data/reports/YYYY-MM-DD-with-ai-deepseek.md` |
| 附 ChatGPT / OpenAI 分析 | `data/reports/YYYY-MM-DD-with-ai-openai.md` |
| 附自定义服务分析 | `data/reports/YYYY-MM-DD-with-ai-custom.md` |

AI 分析按服务商、日期和模式归档，并绑定公开报告内容的指纹。同日期重新联网生成报告后，旧分析也可能失效，必须针对新报告重新生成，或取消勾选保存普通版。正在运行的 AI 请求使用提交时的服务商和报告；中途切换不会把回答误挂到另一份报告。

Markdown 的 AI 部分保留模型、服务商与生成时间，作为引用文字附在数字报告后。它不改变评分、不补造行情，也不是已核实的预测。只保存已有 AI 文字不会再次调用模型；生成新文字才会调用所选 API。尚未配置对应 Key 时，普通报告、历史读取和本机对比仍可使用。独立助手的普通聊天不会自动作为收盘报告附录。

## 读取历史，不必再次联网生成

在「本机历史报告」选择日期，点击 **「读取历史」**。列表最多显示最近 365 个本机已留存日期，按日期倒序排列。读取优先使用本机数据库；没有对应记录时可读取规范命名的同模式 JSON 文件。没有保存过的日期会提示不存在，不会静默请求行情或拿今日数据填入。

加载历史报告后，当前报告日期随之变化；保存、JSON 导出与复盘 AI 以当前显示的报告为准。竞价监测有自己的会话日期，历史复盘不会把竞价会话倒退到过去。进入演示后不能载入真实历史报告，需先返回实盘模式。

原有 `data/reports/YYYY-MM-DD.json` 可以复用，但文件内部日期、模式必须与选择一致；无法确认或格式损坏会提示错误。手工把文件改名成另一日期不会把内容变成那个交易日的报告。

## 比较两份已保存复盘

1. 先显示较新的一份报告。
2. 展开 **「两日复盘对比」**，选择更早的本机报告，点击 **「开始对比」**。
3. 先看覆盖与提示，再看盘面指标、涨停池名单变化和板块变化。
4. 如需归档对比，勾选 **「保存时附上本次对比」**，再点击保存。保存时根据当前与基准两份本机报告核算，不向数据商请求历史行情。切换报告后需重新选择并计算对比。

两期涨停池都必须状态可用、代码有效且无重复、声明数量与实际完整行数一致，才计算共同两期、新出现和退出。任一期不完整时显示不可用，不能解释为「没有共同股」或「全部退出」。例如只保留了榜单前 30 名，不能拿它当完整涨停池。

「共同两期」只表示所选两个日期都在涨停池；「当期新出现」不等于首板，「从对比池退出」不等于已证实断板。只有保存报告的交易日历能确认相邻交易日时才标记相邻；隔日或相邻关系未知时，不推断中间走势。

板块先按完整板块代码匹配两期可得数据，再显示涨幅变化绝对值前 30 项。名次变化为「基准名次 − 当期名次」，正数表示名次上升；不同样本和覆盖会改变相对排名。涨幅差使用百分点，成交额变化使用百分比；分母为零或缺失时不计算比例。日期推断结果标为暂定。板块成交额、排名及其变化均不是主力净流入。

## Markdown 包含什么

- 来源、报告日期、生成/完成时间、真实或 DEMO 模式、报告指纹。
- 盘面涨跌、成交额、涨跌停/炸板、封板比例与近十日连板趋势。
- 涨停强弱前 30 名、严格连板下限、封单额/峰值与因子覆盖。
- 板块量价强度前 30 名、日期归属、成分覆盖与资金口径限制。
- 重点股前复权日线、缺失周期、下一交易日观察清单。
- 全部公开来源警告与质量提示，包括没有进入展示前 30 名的记录；可选两期对比和同版本 AI 文字。相同警告在开头合并摘要并标出涉及数量，文末按消息分组列全字段位置和代码，避免重复提示挤占盘面正文。

观察清单来自当日涨停强度榜前 10 名和已知证据，未自动加入自选，不宣称全市场最优。下一交易日由日历确认，报告不会按星期推定开市日期。原始文本若含编码替代字符，会提示按股票代码核对，不猜测修复名称。

报告不输出密钥、账户配置或原始大体积响应。外部股票名称、警告和 AI 文字会安全转义，不能借文档内容插入脚本或伪造新标题。完整原始证据留在对应 JSON；读取时应结合日期、覆盖和缺失，不能只看分数。

## 盘前就绪检查与页面更新

在「实时竞价」展开 **「盘前就绪检查」**，点击 **「重新检查」**。检查已有配置、今日官方日历、自动监测开关、当日关注池、匹配日期的趋势池，以及竞价期间的本地接收时效和覆盖；09:25 后再看终态。休市日不要求当天竞价终态。

这是一份当时的本机状态检查，不会显示密钥正文、不调用行情或 AI，不代替接口鉴权、未来网络可用性和电脑休眠检查。本机近期收到响应，也不能证明交易所行情近期变化。已处理关注池的比例，与十分钟连续有效观察覆盖是两个指标。

页面通过 SSE 接收状态，数据批次变化时立即推送；空闲时用轻量保活，定期补送完整状态的目标间隔在竞价优先期间为 3 秒，其他时段为 15 秒。断线会尝试重新连接，重连后显示最新状态，不能补回电脑关机时未采集的行情。SSE 的事件和保活方式参考 [MDN：Using server-sent events](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events)。

## 文件与故障处理

演示 Markdown 写入 `E:\A股竞价\data\reports\demo\`，正文标明 DEMO，与实盘同名报告隔离。AI 原文与版本信息写入 `data/ai-reviews/live/` 或 `data/ai-reviews/demo/`，不含 API 配置。

| 提示或现象 | 处理方法 |
| --- | --- |
| 保存按钮不可用 | 先生成复盘或读取已保存历史报告；等待正在进行的报告任务完成。 |
| 没有弹出下载窗口 | 查看页面显示的本机文件路径；也可再次点击下载链接。 |
| 报告已经更新 | 刷新页面，核对新日期/版本后重新保存；需要 AI 时重新分析。 |
| 当前报告没有所选 AI 的专属分析 | 生成该服务商对当前报告的分析，或取消勾选附上 AI。 |
| 只有一份历史报告 | 可正常保存；两期对比要等另一交易日报告实际留存，不能用示例填补。 |
| 对比某项缺失 | 检查两期日期、完整池、覆盖与原始字段，保留缺失；不要按零计算。 |
| 保存文件已被新版本替换 | 原下载链接校验不再匹配；重新点击保存取得当前版本链接。 |

本说明描述已实现功能和数据边界。离线测试、本机浏览器验收、金融接口认证、真实交易日完整十分钟采集，以及真实 AI 生成，是不同的验证项目；具体完成状态查看 [验收记录](VALIDATION.md)，不得互相替代。

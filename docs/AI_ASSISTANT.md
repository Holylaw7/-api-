# 独立 AI 助手使用与复用指南

独立助手版本1.2；本文补充主系统1.6的指定板块AI用法。程序位于 `E:\A股竞价`，后续修改也在此目录。需要 Python 3.10+，使用标准库，无需安装依赖；当前电脑已有Python。

## 第一次使用

双击 `启动AI助手.cmd`，浏览器打开 `http://127.0.0.1:8766`。再次双击会复用已启动的助手。它与 `启动系统.cmd` 打开的竞价研究台（8765端口）是两个独立进程，可单独使用，也可同时运行。

1. 点选 **DeepSeek**，把自己的 DeepSeek API Key 填入密码输入框，点击保存。官方地址与默认模型已预设。
2. 点击「测试连接」。测试仅请求模型列表，不生成回答。成功只证明当前授权可读取列表；模型实际可用性和余额仍以生成请求为准。
3. 在聊天框输入问题，点击发送。当前服务商和模型始终显示在页面上。
4. 需要换成 **ChatGPT（OpenAI API）** 时，点选该选项，填写并保存 OpenAI API Key；之后两家均可直接切换。

这里使用API接入，不使用ChatGPT网页账号、密码或登录状态。金融行情Key、DeepSeek Key、OpenAI Key分别用于各自服务，不能互相替代。程序未内置任何AI Key。

切换服务不会删除另一家的配置或聊天记录。保存配置与选择当前服务是两个操作。请求发出后固定使用当时选定的服务商和模型，切换只影响下一次请求；旧请求的回复仍归属原服务商。

## 结合竞价和复盘研究

普通聊天默认不附加市场数据。要分析股票：

1. 先在竞价研究台完成采集、复盘或按股票代码查询。
2. 在助手中加载本机盘面摘要，查看来源、交易日、竞价日、演示标记和缺失说明。
3. 勾选附加盘面，再发送具体问题，例如“对比摘要中涨停强度前三只股票的封单留存与严格连板证据，区分观察与推断”。

加载摘要本身只在本机完成，不向AI服务发送。提交时发送的是已经预览的快照，期间新增行情不会悄悄替换它；要更新请重新加载。行情主程序不可用时可读取本机最近的有效复盘缓存，页面明确显示缓存日期，不能当作实时竞价。

同一家服务的近期聊天历史会随后续问题一起发送；即使取消本次附加摘要，以前的AI回复也可能已经包含市场分析。需要全新对话时，清空该服务商的聊天记录。切换到另一家不会自动转发原服务商的对话历史。

主系统也可直接在「策略与接入」选择服务商，在「AI辅助研判」生成盘面文字分析。两边共享服务商配置与当前选择，模型Key只需保存一次；独立助手聊天记录与主系统单次研判结果分别管理。

AI只解释结构化结果，不能替代确定性因子。竞价仍按“每批到达→计算→发布”运行，09:25不等待模型。AI不执行交易，输出不回写股票得分或排名。

## 主系统指定板块取数（1.6，端口8765）

在主系统「收盘复盘 → AI辅助研判」中，搜索官方行业或概念名称、选择最多3个板块，即可点击「只读取板块数据」。此步骤只需金融Key，不需AI Key，也不生成回答。板块和同行数据不再仅取普通摘要中出现的前30个板块。

选择AI服务商并点击「联网取数并 AI 分析」后，服务端先为本次选择读取并保存证据，再发送一次模型请求。金融Key始终留在本机，AI只收到`targeted_sectors`显式白名单：每板最多30同行、30涨停成员，保留真实统计、取数日期和缺失说明。目录未匹配不猜测板块，当前成员不冒充历史成员，成交额不作为资金净流入。

全部无有效板块证据、报告版本已变或进入竞价保护时段时，不发起这次模型生成；部分证据可用则明确标partial。没有当前模型Key可继续只取数；系统不会借用其他服务商Key。09:10–09:26暂停新增板块联网任务，实时竞价照常逐批运行。

可以下载独立证据JSON；保存带AI的Markdown后，附录会包含本次问题、板块代码、证据编号与时间。修改问题或板块选择不会改变旧回答，须重新提交。板块补充独立绑定原报告版本，不修改基报告；完整步骤和本机API见 [SECTOR_RESEARCH.md](SECTOR_RESEARCH.md)。

独立助手8766仍采用手动加载本机摘要、预览、勾选再发送的流程。普通聊天或加载摘要不会隐式请求同花顺板块接口；需要自动先取板块再分析时，请在主系统操作。新增主系统板块功能没有把模型变成可任意操作金融接口的代理。

## 模型与官方协议

| 选项 | 默认模型 | API基地址 | 生成协议 |
|---|---|---|---|
| DeepSeek | `deepseek-flash` | `https://api.deepseek.com` | `POST /chat/completions` |
| ChatGPT（OpenAI API） | `gpt-5.6-terra` | `https://api.openai.com/v1` | `POST /responses` |
| 自定义兼容服务 | 用户填写 | 用户填写 | `POST /chat/completions` |

DeepSeek另外预设 `deepseek-v4-pro`；OpenAI另外预设 `gpt-5.6-luna`、`gpt-6-astra`。高级选项允许更改模型ID，账户实际权限以服务商返回为准。内置服务地址固定，自定义服务允许远程HTTPS或本机HTTP。

模型与协议按2026-09-19可访问的官方文档核对：[DeepSeek首次调用](https://api-docs.deepseek.com/)、[DeepSeek生成接口](https://api-docs.deepseek.com/api/create-chat-completion/)、[DeepSeek模型列表](https://api-docs.deepseek.com/api/list-models/)、[OpenAI模型目录](https://developers.openai.com/api/docs/models)、[OpenAI文本生成](https://developers.openai.com/api/docs/guides/text)、[OpenAI模型列表](https://developers.openai.com/api/reference/resources/models/methods/list)。模型会更新，后续维护应重新核对官方文档。

当前使用非流式回答，生成在后台运行，页面显示处理中，不是逐字显示。DeepSeek请求关闭thinking；OpenAI设置 `store:false`，从所有message/output_text段提取正文，不将reasoning当答案。默认输出上限4096 tokens，达到上限会明确标记部分结果，不自动续写。

## 本机保存和发送范围

- `%APPDATA%\hithink-finance\ai-profiles.json`：分别保存服务商配置与Key，位于工程外。属于当前Windows用户的本机凭据文件，不是加密保险库。
- 支持 `DEEPSEEK_API_KEY`、`OPENAI_API_KEY`、`CUSTOM_AI_API_KEY` 环境变量。当前服务商已有保存Key时优先使用保存值，否则才读取它自己的环境变量。
- `data/ai-messages.json`：每家最多40条聊天消息；单次请求最多使用最近20条且不超过5万字符的历史。页面可以清空当前服务商记录。
- `data/ai-startup.log`、`data/ai-server.pid`：独立助手运行信息，不记录请求正文或Key。

空白Key表示保留同一家已有Key。改变自定义服务地址后，旧保存Key和旧环境Key回退都不会继续发送；请明确输入新地址对应的Key。旧版 `auction-lab-llm.json` 首次读取时兼容迁移到custom配置，旧文件保留。

页面状态只返回“已配置/未配置”等信息，不回显Key，不写入浏览器存储。市场摘要通过 `llm.build_summary` 的递归字段白名单生成，保留日期、模式、覆盖和缺失；列表最多30项，较大摘要会进一步缩减榜单。金融Key、程序配置、原始接口响应、本机路径和完整行情历史不会加入摘要。

点击发送会将问题、当前服务商的近期对话和可选的已预览摘要发往所选API，费用与数据处理规则由相应服务商管理。程序不自动换供应商、不跟随HTTP重定向、不自动重试付费生成请求。

## 故障排查

| 提示 | 处理 |
|---|---|
| 请先保存当前AI服务的Key | 检查页面当前服务商，保存它自己的Key |
| 401认证失败 | 重新核对Key及所属服务商 |
| 402/429 | 检查余额、额度和限流；确认请求状态后手动重试 |
| 403/404或当前模型不在列表 | 检查账户权限，在高级设置填有权限的模型ID |
| 网络失败或超时 | 检查联网和对应官方API可达性；请求可能已到服务端，不自动重复收费请求 |
| 暂无本机盘面 | 可先普通聊天；启动竞价研究台生成复盘后再加载 |
| 启动失败 | 查看 `data/ai-startup.log`，确认Python版本和8766端口未被其他程序占用 |

关闭浏览器不退出后台助手；重启电脑后再双击启动。聊天记录保留在本机。不要将Key粘贴进聊天框，请使用专用密码输入框。

## AI与用户二次开发

阅读顺序：本文件 → `CONTRACT.md` → `docs/ARCHITECTURE.md` → `AGENTS.md`。

`ai_gateway.py` 处理配置、跨进程文件锁、服务商协议、错误和文本解析；`ai_studio.py` 管理独立会话、摘要预览与后台任务；`llm.py` 管理主系统市场提示词和白名单；`static/ai.*` 提供独立界面。新增服务商时保留各家独立凭据与历史，不将配置变化放进竞价锁，不把模型输出改成交易指令。

运行 `python -m unittest discover -s tests -v`。测试必须使用临时凭据目录和模拟API，不覆盖用户配置、不调用付费模型。离线协议通过、真实账户连接通过和真实模型回答通过是三种不同验收；当前具体结果见 `docs/VALIDATION.md`。

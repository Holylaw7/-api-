## 1.7.10 页面重启服务按钮验收（2026-09-23）

- 背景：代码或 `data/config.json` 更新后必须重启进程才生效，而 `启动系统.cmd` 检测到 8765 已有服务时会直接复用旧进程（“重新打开还是旧数据”就是这个原因）；用户要求提供页面内按钮，不再依赖命令行。
- 后端：新增 `POST /api/service/restart`。`Service.restart_prepare()` 先校验：09:10—09:26 拒绝、任一同名 job 处于 `running` 拒绝；通过后调用 `stop()` 并返回 `{ok,restarting,mode,message}`。处理器**先发送 HTTP 响应**，再由后台线程关闭监听 socket、关闭 Store、把日志追加到 `data/startup.log`、以隐藏窗口派生新的 `run.py`（同端口）并 `os._exit(0)`；新进程启动时重新读取 Python 代码与 `data/config.json`。`LocalServer(restart=None)`（测试/旧进程）时该端点返回 400“当前进程未提供自动重启入口”，因此自动化测试不会真的退出进程。
- 前端：设置页「02 / 采集范围」底部新增 **「↻ 重启服务（加载新代码/配置）」** 按钮与说明行；点击后弹出确认（会先停止采集、09:10—09:26 与后台任务运行时会被拒绝、约 3—5 秒不可用），随后轮询 `/api/health`，恢复后自动刷新页面；30 秒未恢复会提示改用 `启动系统.cmd`。
- 边界：重启不迁移、不改写任何证据（原始批次已落盘，重启后可用同日恢复逻辑重建会话），未采集数据不补造；不得把该端点改成自动/定时重启，也不得绕过保护时段与后台任务校验。静态文件响应一直是 `Cache-Control: no-store`，所以页面本身不存在脚本缓存问题——此前“刷新无效”是进程未换。
- 回归：`tests/test_service.py` 覆盖保护时段、后台任务、成功路径（拒绝时不停止采集、成功后 `running=False`）；`tests/test_research_service.py` 覆盖 HTTP 路由：无重启入口返回 400 且不停采集，注入回调后触发一次并停止采集（不会真正退出进程）。全项目 540 项测试通过，`node --check static/app.js` 与 `git diff --check` 干净。
- 真实重启验证（2026-09-23 09:5x）：在本机运行实例上先以脱离会话方式启动新版本（`health` 正常、`config.final_grace_seconds=110`），再直接调用 `POST /api/service/restart`：返回 `{ok:true,restarting:true,was_running:false,auto_start:false}`，约 5 秒后健康检查恢复、监听 PID 由 36632 变为 44908、`final_grace_seconds` 仍为 110、`running=false`（保持重启前的“已停止”状态），`data/startup.log` 记录 `[restart] spawn …--no-auto-start` / `spawned pid=44908` / `after 1.5s alive=True`。

## 1.6 指定板块的来源与样本

按 [官方指数契约](https://fuyao.aicubes.cn/docs/api-reference/a-share-index/) 核对，目录每个tag全量返回，无分页；本功能只使用`industry/cn_concept`，不启用区域和特色。搜索在完整目录中匹配名称或完整代码，不依赖原报告板块前30名。未匹配的缩写或方向不推测成另一个官方板块。主服务缓存目录15分钟，真实名称与代码以官方返回为准。

当前成员接口只接受单个指数代码，没有历史date参数。`members_as_of`记录本机取回时间，不能解释为成分生效日期；`membership_basis=current_members_view`明确“当前成员在目标日的表现”。本功能不把当前成员表引入竞价历史调参或宣称无前视的历史板块回测。

每板取截至目标日的60自然日指数日线，指数无复权参数，逐bar的`date_ms`核验日期。成员报价优先复用同报告合格行情；最近收盘日缺少的有限样本可补`stock_quote`，更早目标日只补官方前一交易日至目标日的前复权日线。股票与指数快照的`timestamp`是其中最新有效上游时间，不是逐股时间；采用有限休市推断时保留`provisional/date_verified=false`，不能贴成旧日已核验快照。最新快照字段含涨跌幅百分数原值、成交量股、成交额元；没有名称时使用官方成员名单名称。依据 [股票行情说明](https://fuyao.aicubes.cn/docs/api-reference/prices/)。

每次最多3板块，合并最新报价最多300代码、每批100；历史同行按代码顺序每板最多20、合并最多60个短日线请求，原报告可用行情会减少请求。最近日构建最多10次、历史日最多67次业务调用，目录缓存未命中另2次；重试另计。这些是工程边界，不是官网对普通行情显式代码批量大小或刷新时效的保证。

涨跌分布及成交额统计只覆盖有效行情样本；涨停聚集则以全部有效当前成员与原报告经核验的完整收盘池相交，两者分母不同。严格连板未知不填0，另给`consecutive_known_count`；成分不完整和池缺失分别提示。每板JSON最多100同行/30涨停、AI30/30、页面20/20，截断不改变底层统计分母，也不能以未展示认定未涨停。全部无有效证据时状态为unavailable并停止模型调用。

补充证据独立保存在`data/sector-research/`并绑定原`review_id`，不修改原报告及原评分。模型只收`targeted_sectors`分层白名单及来源/覆盖，不收配置、Key或raw。[主力资金说明](https://fuyao.aicubes.cn/docs/api-reference/capital-flow/)仍标明未开放外部接入，`net_flow`保持null；成交额、龙虎榜净买入均不能替代整个板块净流入。详细字段与例子见 [SECTOR_RESEARCH.md](SECTOR_RESEARCH.md)。

## 1.5 历史竞价与结果标签

本次核对 [官方竞价 REST](https://fuyao.aicubes.cn/docs/api-reference/auction/) 与 [完整指南](https://fuyao.aicubes.cn/llms-full.txt)：`GET /api/a-share/auction/snapshot` 仅有 `thscodes` 和 `stage=live/final`，**没有历史日期参数**。因此仅凭近几日涨停池无法补算完整历史竞价七因子，当前快照不能贴上过去日期。按日期的短线风向标只提供官方选择样本的竞价涨幅等字段，缺少前段金额、换手、量比与后段轨迹，也不能证明当时全候选样本完整，不作为七因子回测替代品。

研究使用三类留存证据：本机实际逐批接收的真实竞价；当时冻结的前日完整池、日历和候选范围；目标日收盘后取得的完整涨停池。原排名时点快照存在则直接保留；不存在时只可按当时记录权重重放并标来源。`data.timestamp` 仍为响应组装时间，不能证明交易所实时发生时点；回放以真正的本机接收时点截断，不把事后下载时间回填成早盘时间。

外部 JSON 须声明提供者、数据版本、金额元、百分数原值、带时区观察时间与当时可见性，由提供者负责核实；程序验证结构不等于验证来源真实性。每次导入 1—40 日且含外层的提交不超过 5 MiB，总计最多 120 日，每日最多 5,000 批，每批最多 100 股；不能覆盖已有本机实盘或另一个导入版本。详细字段见 [BACKTEST.md](BACKTEST.md)，股票代码必须为字符串及完整交易所后缀，缺值用 `null`。

结果标签定义为“是否属于日期一致、完整、在目标日 15:10 及以后取得的涨停池”。15:10 是本地研究门槛；官网未承诺这就是永不修订的最终池。分页失败、缺池与未知保持缺失，不能记为未涨停。上下文固定昨日涨停候选，自选和趋势股只有当时采集的批次才存在，当前参数研究不声称已验证所有自选或全市场。

截至升级核查，本机只存在演示竞价记录，不能得出真实七因子改善结论；已留存十日完整涨停池只能计算延续基线。原始批次和每日档案不因调参主动清理；实验读取和外部 AI 开发集均为本机操作，不额外拉取历史行情。完整导出可能含保留日期结果，自动调参应使用专用开发集出口，避免用检验标签选参数。

## 代码解析、独立研究与趋势池

[官方证券搜索文档](https://github.com/HiThink-Tech/Financial-API/blob/main/docs/api/meta/tickers-search.md)允许模糊搜索，本系统只把其中**唯一、精确的A股代码匹配**视作确认：资产类别必须为 `a-share`，`thscode` 必须是六位加 `.SH/.SZ/.BJ`，`ticker` 必须等于前六位，交易所字段不能冲突。裸六位只匹配完全相同ticker，完整代码只匹配完全相同thscode；不接受名称查询或按前缀推测后缀。

代码在输入、JSON、自选和缓存中始终为字符串，例如 `"000001"`，不得转成整数。`stock-metadata.json` 记录官方名称、资产类型、解析输入和来源。只有先前对同一裸代码做过官方确认的缓存，才能复用其唯一性；缓存里刚好只出现一个完整代码不等于官方只存在一个匹配。

独立个股分析由 `stocks.py` 调用[官方A股历史日线](https://github.com/HiThink-Tech/Financial-API/blob/main/docs/api/a-share/prices-historical.md)，一次只取一个证券、最近40个交易日，截至用户指定或最近已收盘交易日，明确前复权。禁止当前或未来快照补足历史缺口。结果存 `data/stocks/完整代码-日期.json`，来源记录请求起止日、前复权、原始时间、最新有效K线日期及一次请求标记。SSE附加的本机竞价记录另标会话日期，不属于这次历史接口请求。

自动趋势池由 `selection.py` 构建。优先复用同截止日报告 `raw.market` 的活跃股及 `raw.pools_by_date` 的最近5日完整涨停池；缺少池时才补请求。报告活跃股最多优先40只，再补近期池，最多评估60只、入选30只。无报告或行情日期不可用时仅用近期涨停池。活跃股快照若使用有限休市日推断，须保留明确标记并按报告 `completed_at` 复核推断条件；不得仅凭一个推断布尔值忽略日期。

市场快照没有名称时由官方代码表补充；无法确认名称、ST/退市标记或代码格式不合格的候选不参与自动筛选。每只候选只读取截至目标日的最近60自然日前复权日线；硬阈值与筛选评分见策略文档。`trend-pool.json` 保存候选数、评估数、有效历史数、未评估数、入选数及质量提示，不能把有限样本称为全市场搜索。

三种覆盖不可混用：竞价和独立日线强弱的覆盖为有效**权重**和；趋势筛选的 `score_factor_coverage_pct` 也是权重覆盖，缺10%量能因子时为90%；复盘涨停/板块的 `factor_coverage_pct` 则是有效因子数量占比。前复权历史可随公司行动或供应商修订变化，当前取回的历史并非当时冻结版本。

独立查询不自动加入自选。新增关注核验成功后从下一轮采集，不补之前没有观察到的竞价；移除仅取消手动来源。保护时段09:10–09:26只展示已有本机观察并延后日线，09:27之后继续；趋势筛选中断时标记partial并保留覆盖。模型调用不参与上述数据采集和数字计算。

## 实时性边界

竞价快照的 `data.timestamp` 是**接口响应组装时间**，不是逐笔行情时间或证券交易所的源时间。系统不能据此证明每个标的都是同一毫秒的行情，也不能宣称已经取得交易所级完整逐笔委托。

实时采集应当每收到一批就调用引擎、更新排名并持久化。一次请求最多100只。全市场循环时，各批时间不同；候选集、单批耗时、实际覆盖率、轮询周期及终态标志必须保留给用户。官方文档没有承诺延迟 SLA，无法对上游数据尚未就绪时的09:25结果完整性作无条件保证。

常规接口对网络错误、HTTP 429/部分5xx、业务4001/5001/5002/5003最多额外重试3次，基础指数退避0.5、1、2秒。兼容`Retry-After`的秒数及HTTP日期格式；如果要求等待超过15秒，不把它截短为15秒再立即重试，而返回受控错误供调用方以后处理。常规默认超时6秒。1xxx/2xxx、3002等不进行内部盲重试。

**竞价请求不进行内部重试**，每批只有一次带超时的请求；下一轮及有限终态补采窗口由调度器负责，避免一次限流拖慢所有后续股票。所有相同 Key 的客户端实例共享最小请求间隔，默认0.5秒。复盘是后台工作，竞价窗口不应同时启动大量复盘请求。

1.4另外在同一进程的同Key实例之间共享HTTP429/业务4001冷却；冷却中不发新的上游请求，公开状态显示剩余等待。官网现述“当前不限制累计调用次数”，同时明确会根据负载动态限流，不能推导出无限并发或稳定QPS。Retry-After解析属于本机工程兼容；官网没有承诺一定返回该头，也没有据此给出竞价延迟SLA。

## 收盘复盘口径

1. 最近10个交易日逐日读取完整涨停池，另取目标日跌停、炸板池。天梯仅附原始旁证。
2. 涨停股强度：早封25% + 当前/峰值封单额比30% + 封单额横截面分位25% + 严格连板高度20%。早封按交易分钟计算，午间休市不计，09:25竞价涨停视作最早。连板高度7板及以上封顶100。
3. 任何因子缺值保留 `null`，使用其余可用权重重新归一化；`factor_coverage_pct` 和 `quality` 给出覆盖率。低覆盖率分数与完整因子分数比较时需结合缺失提示。
4. 晋级率 = 上一交易日完整涨停池与本日池交集数量 / 上一交易日完整涨停池数量。分母包括首板，按上一日严格连板高度分组。分母为0时比例为空；上一日请求失败时分母及晋级率为空，不是0%。
5. `N连板`、`首板`、`N天N板`可以提供明确连板标签；`5天4板`一类非连续描述不直接取4。逐日池中连续出现可独立验证严格连板，遇窗口边界或缺失日标注下限；标签与逐日证据冲突时标注冲突并采用可观察记录。原始 `continue_day_cnt` 仍保留供核对，但不直接作为严格连板。
6. 近10日趋势展示每日涨停数、严格连板数、最高高度、晋级率；当前涨停股展示窗口出现次数、最近5日出现次数、可观察日数和连续段。它们是已发生行为的描述，不是未来涨停概率。
7. 盘面涨跌家数只统计有效 `price_change_ratio_pct`；缺值不当作平盘。成交额只加总有效值，同时展示覆盖率。封板率为涨停池数量 / 涨停池与炸板池代码去重并集数量，不是逐笔委托成功概率。

目标日涨停强度前20名还读取截至目标日的最近60个自然日前复权日线。只允许请求窗口内、日期有效且不重复的K线参与计算；未来K线即使上游返回也会被排除。按交易日历展开日线，缺少交易日不能拿更早的有效K线顶替，以免将“5个交易日”误算成“任意5根有效K线”。没有目标日K线时，整组目标日趋势指标为空。

| 个股趋势字段 | 定义 |
| --- | --- |
| `close`, `ma5`, `ma10`, `ma20` | 目标日及最近5/10/20交易日的前复权收盘价与均线；不足周期或周期内收盘价缺失时对应均线为空 |
| `above_ma5/10/20` | 目标日前复权收盘价是否严格大于对应均线；相等为false、无有效比较为null |
| `return_5d_pct` | `(t日收盘 / t-5交易日收盘 - 1) × 100`，需要第6个交易日的基准收盘价 |
| `volume_ratio_5d` | 目标日成交量 / 此前5个交易日成交量均值；均值不含当日，缺量或分母为0时为空 |
| `max_drawdown_20d_pct` | 最近20个收盘价从先前运行最高值至后续较低收盘价的最大回撤，正百分数；上涨序列为0，不使用盘中高低价 |

报告每只股票的 `price_trend` 保留状态、截止日、复权方式、K线数量及警告，`trend.price_coverage` 说明请求数量、可用收盘价数量、完整指标数量和20只上限。未进入日线样本的股票仍保留涨停/连板池趋势。日线没有目标日记录、数量不足、上市较短或停牌都会影响指标覆盖，不能补造。

前复权由上游按取数时提供的复权因子计算。历史报告是回顾性分析，不是保存当时可见公司行动信息的无前视回测数据库；不能由当前复权序列推断历史交易时已知所有后来公司行动。

报告原始证据位于 `raw`：逐日涨停池、跌停/炸板池、全市场行情、板块目录、每批板块行情、获取到的板块成分、历史样本日线及天梯。数据读取失败保留 `null`，报告 `status=partial`，`warnings` 给出原因。输出报告可用于用户核对和后续AI复用；大结果应保存在本地，不在日志逐行展开。

## 板块“资金强弱”的可实现范围

官方 [资金流向快照](https://github.com/HiThink-Tech/Financial-API/blob/main/docs/api/a-share/capital-flow-snapshot.md) 和 [资金流向历史](https://github.com/HiThink-Tech/Financial-API/blob/main/docs/api/a-share/capital-flow-historical.md) 均标注 **端内专用、待上线、当前不可调用**。API Key 不等于具有此能力。系统因此不调用这些路径，也不会把成交额、涨幅或封单额命名为“主力净流入”。真实净流入字段固定 `null`，`net_flow_status=unavailable`。

本版板块榜使用**价格强度与成交参与度代理**：全部行业及概念板块有效快照中，涨幅分位60% + 成交额分位40%。同值使用相同中间分位。行业、概念在同一横截面排名，较大板块成交额天然占优；可在界面按类别比较。这个分数不能辨别资金主动买入/卖出，更不能表示净流入金额。

按统一分数排名前30个板块额外读取当前成分，展示成员数、涨停数、连板数和涨停密度。前30之外仍有完整行情排名，但成员归属指标为空；附加成员信息不改变榜单评分，避免因部分板块数据更丰富而偏置排名。`sectors.coverage` 明确全目录数、可排名数、已归属数和上限。概念成员可重叠，各板块成交额或涨停家数不能跨板块直接相加。

## 日期对齐与历史限制

行情快照为最新行情，不带历史日期参数。默认只有行情时间戳转换到上海时区后的日期等于报告日期，才用于报告；不同分页跨日拒绝直接合并为同一日盘面。上游缺少单只时间字段，无法额外证明每行均同一时点，保留原始批次时间。

**已观察到的文档差异（2026-09-19）**：实际认证请求中，全市场5575条行情、56页，以及行业和概念合计710个板块，快照时间落在周六2026-09-19，而本次交易日历最后交易日为2026-09-18。官方价格文档仍描述为“最新上游有效时间”，仓库客户端只是转发数据，没有可核实其服务端组装逻辑的实现。因此本系统不据此断言这些时间一定是响应组装时间，也不把周六原始时间改写成周五。

针对这一实测情况，提供**有限且暂定的休市日归属推断**，以下条件同时成立才会使用：

- 交易日历在本次复盘中成功重新读取；至少有20个合法交易日，最早日期不晚于今日前30天，且不含未来日期。少量或明显过期的日历不构成休市依据；该数量检查不能独立证明上游日历内容无误。
- 今天不在该日历中，目标日正好为日历最近交易日，距离今日为1至14个自然日。
- 快照原始日期为今天，时间不晚于实际收到响应时的本地时间；本次复盘跨自然日时停用推断。
- 全市场每页时间戳均存在，所有页日期只能属于目标交易日或今天；任何更旧页、无日期页或未来页都会拒绝推断。

触发时保留 `snapshot_date`、`snapshot_timestamp`（及原始 `timestamp`），增加 `effective_trade_date` 作为**推断**归属，`date_basis=inferred_latest_closed_session`、`date_verified=false`、`data_status=provisional`；市场、板块及整份报告均为 `partial`，并显示未独立核实日期的警告。板块每行保留相同标记，`coverage.inferred_date_count` 明示涉及数量。不同批次的重复警告会去重。这些值可供观察，不能当作已逐股验证的历史收盘归档。

目标日更早、今天为交易日、日历缺失或明显不完整时，没有此例外。直接时间戳吻合时 `date_basis=snapshot_timestamp`、`date_verified=true`，这里的true仅表示接口时间戳日期匹配，不表示已验证每一证券的独立行情时间。

选择历史日期时，涨停池、晋级率与近10日趋势仍按请求日读取；当前全市场行情不会冒充当日涨跌家数或当日成交额。历史全市场盘面需要另接当日全市场快照归档或合规日线数据仓库，本版留空并说明。

为限制历史单代码请求数量，历史板块日线默认只读取**目录按代码排序前30个行业**，不按今日涨幅选历史样本，避免引入未来赢家选择。其余行业及概念保留全目录，但历史行情及分数为空。历史成员归属未提供，不用当前成员伪装成过去的板块结构。报告显示 `historical_sample=true`，不能宣称完成了历史全板块排名。今后可以通过本地逐日归档或批量日线数据源扩大全覆盖。

## 接入真正资金流数据

`app/review.py` 中 `CapitalFlowSource` 协议预留独立接口：

```python
class CapitalFlowSource(Protocol):
    def sector_flows(self, date: str, sector_codes: list[str]) -> dict: ...
```

适配器应返回 `date`、`currency='CNY'`、`definition`（例如超大单+大单）、`source`、`timestamp` 和 `rows`，每行含 `thscode`、`inflow`、`outflow`、`net_flow`；缺值保留 `None`。新增源应先验证授权、覆盖日期、金额单位、净额计算定义和板块重复归属规则，再在复盘服务中显式合并结果。接口协议已预留，默认没有安装或调用外部资金流服务。

如果外部源仅提供股票资金流，应注明按当前成员聚合还是历史时点成员聚合；概念重叠不能被误解为全市场净额。应独立展示真实净流入及参与度代理，保留来源和覆盖率，不把两者混成一个无来源分数。

## 凭据与可复现性

请求头携带密钥，URL不允许密钥查询参数，禁止向不同域名或HTTP明文重定向转发凭据。错误仅显示受控中文说明、错误码和安全请求ID，不显示上游任意报错正文；客户端 `repr` 隐去密钥。不要在测试夹具、报告、LLM提示或版本管理中保存真实密钥。

`tests/test_provider.py` 与 `tests/test_review.py` 全部使用明确的模拟夹具，不访问真实市场，也不以模拟结果替代正式模式。可运行 `python -m unittest tests.test_provider tests.test_review -v`；测试覆盖协议信封、完整分页、限流边界、实时单次请求、日期错配、严格连板、完整池晋级分母、资金流缺失、全目录/部分归属覆盖率。

## 1.3 本机报告与两期对比的数据来源

「读取历史」「开始对比」「保存 Markdown」只读取本机 SQLite 或已保存 JSON，不调用金融 API。新数据仍由「联网生成复盘」或自动复盘取得；没有历史归档的日期不能通过导出操作补齐。目录显示最近最多 365 个已存日期，实盘/演示按模式隔离。

Markdown 保留原始快照日期、有效交易日期、推断/核实标记、模块覆盖及公开警告；榜单截取前 30 名不影响完整缺失说明。JSON 继续保留原始证据；Markdown 不包含 raw、密钥和配置。普通版与按服务商命名的 AI 版分别落盘，AI 附录必须与报告日期、模式和公开证据指纹一致。

两期涨停池比较须同时满足每期 `status=ready`、代码有效且无重复、声明总量等于完整行数。否则共同、新出现、退出数量保留为空。比较两日集合不自动证明连续连板或断板，是否相邻须由已有报告日历确认。板块按完整代码在两期可得列表匹配，日期不符时不算变化；休市日推断值继续标 `provisional`。成交额不变成净流入，样本不同产生的名次变化也不解释为真实资金轮动证据。

「盘前就绪检查」仅评估本机已知状态，不发送鉴权请求；配置已存在不表示账户权限已验证。本地接收时效仍不能替代交易所行情时间，关注池处理覆盖不能冒充十分钟窗口覆盖。

## 1.4 官网完整指南的使用范围

`sentiment.py`不引入新来源：梯队矩阵复用已保存的`raw.calendar/raw.pools_by_date`，封单和原因分布复用完整当期涨停池。使用`limit_up_reason`原文，不调用只支持当日的个股异动接口来填历史原因，不使用当前成分表作历史归因。空池、缺失、重复代码、日期错误分别处理；统计公式见策略文档。

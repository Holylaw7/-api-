# 1.4 官方指南升级说明

本版依据2026-09-20核对的同花顺[接口总览](https://fuyao.aicubes.cn/docs/api-reference/overview/)、[完整指南](https://fuyao.aicubes.cn/llms-full.txt)和[最佳实践](https://fuyao.aicubes.cn/best-practices/)，补充收盘证据并改善取数可靠性。项目继续在 `E:\A股竞价` 运行，双击 `启动系统.cmd` 打开主程序；独立AI助手仍用 `启动AI助手.cmd`，DeepSeek / ChatGPT切换方式不变。

## 每日怎么用

1. 在「收盘复盘」生成已收盘日的报告，或从本机历史列表读取一份报告，确认页面显示的日期。输入框改变日期本身不会切换当前报告。
2. 查看「涨停情绪结构」：近十日连板矩阵、封单留存分布和官方涨停原因原文。旧报告也能在本机计算，读取不新增行情请求，不改写旧报告身份。
3. 生成复盘时已自动读取当前报告日期的短线风向标与全部／机构／游资龙虎榜（分项失败只提示，不影响复盘）。需要重试或晚间刷新时点击 **「联网补充官方观察」**，它按当前报告版本重新读取这四项，完成后显示各自状态和数据覆盖。
4. 需要模型解释时选择DeepSeek或ChatGPT，为更新后的报告重新生成AI研判。补充前的AI回答对应旧版本，不能直接附在新报告中。
5. 点击 **「保存 Markdown ↓」**，保存到 `E:\A股竞价\data\reports\YYYY-MM-DD.md`。勾选同版本AI附录时另存为带服务商后缀的文件；可继续使用原有两日对比附录。保存先本机落盘，浏览器下载行为由浏览器设置决定。

补充按钮只支持已保存、有原始交易日历证据的已收盘真实报告；09:10–09:26优先保障竞价，演示模式不请求真实数据。若旧报告缺少日历证据，先用「联网生成复盘」重新取得该日报告。龙虎榜只支持一年内交易日，超过范围时显示分项不可用，不换日期凑结果。

收盘复盘（自动15:10与手动相同）会按同一套显式日期、逐分项可取消的规则读取这四个分项：可用就直接写进新报告，`partial` 只加“部分缺失”警告，`unavailable`/取消/异常只加警告，不阻塞复盘，也不把原盘面缺口升级为完整。龙虎榜通常在收盘当晚才发布，15:10 自动取得的分项可能暂为未就绪，稍后点 **「联网补充官方观察」** 可改为 ready 版本（已有 ready 不被新的 partial 覆盖）。最多四个业务分项不等于总共四次HTTP请求：网络或限流触发常规重试时，实际请求可能更多。模型分析与竞价分批读取仍相互独立。

## 情绪结构怎样理解

连板矩阵使用报告中已留存的完整涨停池，而非官方每个板位最多四只的天梯样本。至多展示十个目标日前交易日，按1、2、3、4、5板及以上和未知高度分档，各档互斥。窗口不足或缺失日形成的连续段只表示下限，1板下限不表示已确认首板；失败日不显示零涨停。

封单留存为当前封单额除以峰值封单额，展示有效样本中位数和低于50%的比例。缺值、负金额、峰值不大于零及当前额超过峰值的异常都不计入有效样本。它描述涨停池快照封单结构，不能等同早盘竞价金额留存、真实撤单率或成交概率。

原因分布只按官方`limit_up_reason`完整原文归组，占比的分母是有有效原因文本的股票。最多展开30组，每组最多10个代码，`group_count`保留总组数并提示未展开数量；可以按代码进一步查询同日报告。没有原文就显示缺失，不让AI补写，不将原因词语当作行业或经验证的价格因果。

## 两类官方补充数据

| 数据 | 显示内容 | 阅读限制 |
| --- | --- | --- |
| 短线竞价风向标 | 官方样本数、有效涨幅数、平均/中位竞价涨幅、上涨占比、标签和前30只 | `auction_pct`已经是百分数原值；0是有效样本但不算上涨。不是全市场宽度，不改变原竞价七因子。 |
| 全部龙虎榜 | 股票上榜记录及龙虎榜净买入 | 金额元，只涵盖上榜证据，不等于全市场或板块主力流入。 |
| 机构龙虎榜 | 机构净买入 | 与全部榜有重叠，不能相加。 |
| 游资龙虎榜 | 游资名称与关联股票，某游资在某股的净买入 | 上层聚合金额不能按每条股票重复累计；上游记录/股票数和游资展开记录/股票数范围可能不同。 |

龙虎榜按1日、3日及未知区间分开，每榜每区间最多显示30条，完整原始结果留在JSON。全部榜按全部净额、机构榜按机构净额、游资榜按该游资个股净额排序；缺值末尾，同值稳定排序。同股同区间可能存在多条记录，未取得可靠互斥规则前不擅自累计或只留最大值。`limit_reason`是官方涨跌停原因，不是监管要求上榜的触发原因。

全部榜与机构榜核对上游声明记录数、去重股票数和实际行数，不一致则提示partial，不能把声明非空而收到空数组称为完整空榜。游资上游计数与展开股票样本范围不同，分别显示且完整覆盖标为未知，不能直接用两者相除。

本版不做概念资金归因。[最佳实践16](https://fuyao.aicubes.cn/best-practices/16-dragon-tiger-capital-flow/example.html)提到的多概念等分只是研究计算口径，不会让龙虎榜变成真实板块主力资金流。[官方主力资金模块](https://fuyao.aicubes.cn/docs/api-reference/capital-flow/)仍未对外开放，因此原板块榜继续展示价格与成交参与度。

## 状态、日期与失败处理

- **ready**表示该层已按约定解析，仍须阅读样本范围和覆盖说明；不是收益、全市场覆盖或交易所时效保证。
- **partial**表示部分数据缺失、异常或证据冲突。未就绪和失败分项为null，不能当作当天没有记录。
- **全部不可用、取消、报告被其他任务更新：**原报告保留；按提示稍后重试。原来已ready的补充不会被新partial结果覆盖。
- **原行情报告的partial：**补充成功也不会将它升级成完整盘面；两层状态独立。
- **Markdown文件被占用：**补充证据可能已经保存、报告版本已经更新，仅Markdown写入失败。关闭占用文件后点击「保存 Markdown ↓」即可本机重试，无需再次联网补充。多种文件不构成整体原子事务。

风向标响应date和date_ms必须分别吻合所选报告日及上海零点；其timestamp只是组装时间。龙虎榜按trade_date核对，timestamp另按日零点交叉检查。官方文档示例本身出现过这两项不一致，系统不会按示例硬编码或静默修正；矛盾公开标partial。详情和对应数值在 [数据来源](DATA_SOURCES.md)。

新增证据会生成新的review_id。同一日期的旧AI文字即使文件仍在，也不能被当成对新证据的解释。单纯打开旧报告计算情绪视图不更改review_id；重新取数和正式补充才产生新证据版本。

## 接口可靠性与复用

官网说明当前没有累计调用次数限制，但会根据实时负载动态限流。系统保留请求间隔，遇HTTP429或业务4001，在同一进程使用同Key的请求之间共享冷却，界面显示剩余等待。已有报告、竞价观察和本机统计可继续阅读。Retry-After解析是工程兼容，并非官网保证提供的响应头；不能由冷却倒计时推定服务必然恢复。

涨停池分页现在同时核验请求回显、总页数、页间总量、每页应有记录数和代码唯一性；跨页变化会明确失败，不将截断数据伪装完整池。实时竞价仍是一批到达即落盘、评分、发布，网络层不内部重试竞价批次；这次升级没有把十分钟合并到最后分析。

给后续用户、开发者或AI复用时，先读 [AGENTS](../AGENTS.md)、[契约](../CONTRACT.md)及[架构](ARCHITECTURE.md)。纯统计入口是`sentiment.build_sentiment(report)`；有界补充入口是`official_context.build_official_context(provider,date,should_stop)`，由Service负责日期许可、后台执行、报告版本检查和持久化。数据通过API直接访问官网，ignored work目录的研究缓存不是运行依赖。

Markdown输出保留新统计、日期、区间和缺失信息；AI出口为`llm.build_summary`显式白名单，榜单等列表最多60项（超过15万字节时依次降到30、10并在`scope_note`声明），榜单另附`shown/available/total/truncated`，龙虎榜每榜每区间最多10条，raw、配置和未知字段留在本机。DeepSeek、OpenAI和自定义服务继续分别保存配置；独立助手仍须先预览再选择附带市场摘要，不因更新自动发送报告。

本次取舍还纠正了[最佳实践12](https://fuyao.aicubes.cn/best-practices/12-limitup-sentiment-timing/example.html)已过时的“无炸板池”描述：现行完整指南已经提供炸板接口。官方示例用于设计参考，字段规则以现行REST指南为准。离线回归、真实授权和完整交易日验收是不同证据，具体执行记录另见 [验收记录](VALIDATION.md)。
